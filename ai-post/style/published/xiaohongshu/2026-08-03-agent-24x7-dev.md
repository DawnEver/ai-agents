## 正文（粘贴到平台编辑框，不进图片卡）

让 Agent 通宵迭代，我烧穿过 20x Claude Max 的额度后，才想明白一个事：软件开发不再是怎么写代码，而是怎么运行一个优化器。

本质就是把一句模糊意图变成确定性机器代码——这是个多目标优化：语义正确、系统稳定、token 省，三个还互相打架。原则就三条：目标函数必须诚实、边界必须显式、预算必须实测。

7×24 怎么跑？主 Agent 维护一棵计划依赖树（每个节点只留任务编号、状态、500 token 内摘要、后续任务编号），记忆系统 rem 跨会话续着计划；主 Agent 绝不亲自写代码，派 subagent 干，保主会话上下文；收敛交给统一 gate 判 PASS/FAIL，不靠人记。优化在三个目标间权衡，但验收只认一个综合目标函数。

一句话：主 Agent 从写代码的人，退位成调度优化器的控制器。

## 分页文字卡正文（全文细节，渲染进图片卡）

软件开发，正在变成一个优化问题。

最扎心的一次：Agent 跑通宵，pytest 全绿，第二天我试那功能，完全不是我要的东西。问题不在代码，在目标函数——我从没告诉它「什么才算对」。软件工程，就是把人类的自然语言意图，转化为确定性的机器代码。Agent 不再一步写对，而是反复迭代实现——本质是多目标优化器在解空间搜索三个互相打架的目标：

- 语义正确性 —— 代码对不对得上用户模糊的意图。失败症状：能跑，但不是用户要的。
- 系统稳定性 —— 边界和异常下是否扛得住。失败症状：正常路径全绿，边界路径静默出错。
- 计算成本 —— 步数、API 次数、token 和时间扛不扛得住。失败症状：上下文打满、烧穿 token、超时。

三者必须显式化为可度量的目标函数，而不是「尽力把事做好」。

- 第一约束是诚实：优化器沿目标函数走，函数撒谎，走得越远越错
  - 准确是标签不是门槛：f1 必须量化，加机器可读精度标签、加实测偏差的 warning，绝不编造数字
  - 声明不得撒谎：docstring、注释、类型提示、状态必须代码强制查阅；守卫范围撒谎最危险，范围声明要有专属测试
  - 验证是否真修复：revert it, keep the prose, run the suite——回退修复、保留文档、重跑套件，看它是不是又红
  - 实现而非排除：别用能力守卫挡掉不精确的组合，隐藏约束会遮蔽真实解空间

- 系统稳定性是一等目标：f2 判据不是不崩，是每个失败模式都被显式声明并可达
  - 不支持的组合直接抛异常（RAISE），绝不静默失败
  - 适配器返回完整干净的输出，半模型不泄露到组合层
  - 禁止 waivers、fallback、_legacy 包装——别偷偷兼容旧逻辑
  - 要下线一个能力，明确标记 retired 进 retired.py，让测试覆盖它确实下线了

- 计算成本与时间预算是硬约束：f3 是约束不是目标，成本超限层就不存在
  - 分级时间预算（经验值）：冒烟 5-10 分钟、阻塞门 30 分钟以内，其余永不阻塞
  - Token 硬约束必须实测：我实测 20x Claude Max 对一个求解器项目都堪堪不够，额度要按项目规模真计量
  - 分层调用模型：贵模型做决策，便宜模型（fabric 调 deepseek/codex）搬砖；用 token 换 token

- 7×24 迭代组织：从一次会话变成持续运行的优化器，把记忆与计划从会话上下文里解放出来
  - 计划依赖树是主干：每个节点只留 Task_ID、状态、500 token 内摘要（Context_Digest，经验值）、后续任务编号（Follow_up_Ids）；rem 记忆跨会话持久化，goal 要求完成全部计划及 follow-up
  - 主 Agent 绝不亲自重度编码，fan-out subagent 派活，保主会话上下文
  - 收敛由统一 gate 自动裁决（PASS / FAIL / INCONCLUSIVE 三态），不用手写测试脚本人工判断
  - 优化在 f1/f2/f3 间权衡，但每次验收只认一个综合目标函数，绝不写评判它的 bar

一句话总纲：Agent 时代，软件开发就是一个持续运行的多目标优化器——语义正确、系统稳定、成本受控。原则只有三条：目标函数诚实、边界显式、预算实测。主 Agent 从写代码的人，退位成调度优化器的控制器：在 token 烧穿之前，知道该让谁去干。
