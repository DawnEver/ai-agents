# Agent 24x7 文章 pipeline + 小红书双正文机制 (2026-08-02)

## 做了什么
跑 `/post-new agent-24x7-dev`，主题=「Agent 时代，大型软件开发成为一个优化问题」：让 Agent 7×24 迭代的工作流 + 软件开发=多目标优化（语义/稳定/token 成本）框架。source 为本地 personal 方法论笔记（persona=author）。

- 调研 + 四平台 v1 → 用户多轮评审 → v4。**Twitter 在 v4 被用户要求砍掉**，最终平台：小红书 / 微信 / 知乎。
- 用户提供了**权威底本**（原则文档，非经验分享），存为 `ongoing/agent-24x7-dev/1-research/master-v4.md`。底本有几处粘贴损坏片段，我按意图修复（如「节点_Digest」→「Context_Digest≤500 token」），修复处均向用户标注核对。
- 小红书标题定为「Agent时代，软件开发是运行优化器的规则」。

## 持久机制改动（重要）
**小红书「双正文」机制** — `scripts/post-publish/gen_xhs_pages.py` 的 `parse_article` 现在识别两个区段标记：
- `## 正文（粘贴到平台编辑框，不进图片卡）` — 精简版，贴进 App 正文框；**排除出卡片**
- `## 分页文字卡正文（全文细节，渲染进图片卡）` — 完整细节，脚本拆成 3:4 分页文字卡
- **旧文件无标记 → 照旧渲染 H1 后全部正文（向后兼容，测试通过）**。
- 机制已写入 `templates/xiaohongshu.md` + `.claude/skills/post-publish/_platforms/xiaohongshu.md`。
- 落地场景：小红书正文装不下全部细节时，「全文细节进图片卡 + 正文放一版」。

## 持久学习：用户反感模板过拟合（重要）
用户明确批评「被模板整得过拟合，连真诚文章都不会写了」。多轮 feedback 方向：
- **要真诚的经验分享/见解，不要商业/营销/种草腔**；不要拉互动的 CTA（「评论区聊聊」「把账单故事甩给我」）。
- 避免钩子式标题/煽动开场（「额度先烧穿了」）；用平实叙述（「额度比我想的费得多」）。
- 不要「教唆/该这样」的布道腔；落点是「我的取舍，不是标准答案」。
- **写稿不要完全套模板结构**——被模板公式牵着走会丢真诚。先写成真诚的第一人称复盘，再按平台长度落稿。

## token 口径
- 20× Claude Max 额度对求解器开发一个大型项目都堪堪不够——真实实测，写作红线之一；不出现具体项目名。
- 无虚构案例；不编造数字。
